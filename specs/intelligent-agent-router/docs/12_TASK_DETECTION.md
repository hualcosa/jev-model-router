# Task detection — core implementation, not host integration

`router_core/boundary.py` is a pure frozen-state root gate. State is scoped to runtime/project/session. It recognizes leading `/new-task`, explicit preflight, and trusted native TaskCreated. Meaningful initial requests need task intent, not only length. Explicit topic-shift requests can concern the same repository/vocabulary; disjoint vocabulary without that cue is not proof of a new objective. Ambiguous follow-ups/logs abstain. EN/PT acknowledgments, root continuations and internal tool/child events never trigger root classification.

Stable event/turn identity is required for new automatic assessment. Native TaskCreated uses native task identity, allowing multiple tasks in one turn without suppressing the second. Resume/compaction/reset occurs before receipt dedupe. Stop is not completion; only trusted matching TaskCompleted closes the native task. TTL only invalidates evidence, never establishes novelty; nonfinite or regressed clocks do not enable classification. Token hashes are bounded features, not semantic task identity; raw prompt/objective vocabulary is not retained. Logical IDs hash runtime/project/session/counter, not task text. Warning fingerprints and receipt history are bounded. Persistent storage and cross-process atomicity are still RTE020 work.

`router_core/spawn.py` recognizes only native PreToolUse creation tools in an injected verified runtime/surface/version/schema profile. Profiles cannot repurpose Bash, hide the native agent-type field or call an arbitrary custom profile generic. Existing non-null model/effort values (including empty strings) bypass immediately. Unrelated tools, missing identities, unknown fields/types, multimodal input, invalid encoding or unsupported versions abstain. Verified scalar/boolean arguments are preserved in an immutable bounded copy; task text and arguments are absent from repr/telemetry.

Claude plaintext tasks produce a TaskEnvelope with deterministic scoped tool identity. Current Codex opaque messages are required/validated only as bounded text, never decoded or interpreted. They produce `prepared_task_required` plus a stable task ID; task_name is not classification evidence. The ADR006 local reference/preparation path still needs production wiring.

A thread-safe bounded tracker demonstrates at-most-once recognition in one process and refuses new keys at capacity without evicting/reallowing earlier ones. It is NOT cross-process hook dedupe. RTE020 must coordinate independent hook processes and prepared references before E2E acceptance.

Verification: 28 boundary +24 structural spawn test methods, plus nine policy tests and named golden fixtures. Complete regression at this checkpoint:466 tests pass in pinned SDK interpreter; default interpreter has two optionalSDK skips. No new native host or desktop integration claim is made by these unit tests.
